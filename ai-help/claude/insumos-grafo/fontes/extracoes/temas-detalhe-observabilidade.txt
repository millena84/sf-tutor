tema: Observabilidade, auditoria e operação (rodada A4)
obtido em 2026-11-16 por busca restrita a help.salesforce.com e developer.salesforce.com (WebSearch).
método: leitura_resultado_busca. As páginas NÃO foram abertas por inteiro: só o trecho devolvido pela busca foi lido. Paráfrases em português.

[src:apex-debug-log] Debug Log (Apex Developer Guide, apex-debugging-debug-log.html): logs de depuração podem ser guardados para usuários, classes e
  triggers. Trace flags de classe e de trigger mudam o nível de log, mas não fazem um log ser gerado. Cada log tem até 20 MB; acima disso, linhas
  antigas são removidas. Logs de depuração do sistema ficam guardados por 24 horas.
[src:help-debug-logs] Debug Logs (platform.code_debug_log.htm): um log é gerado quando há trace flag de usuário ativa, quando se rodam testes Apex e
  quando o código ou a requisição de API traz parâmetros ou cabeçalhos de depuração. Ao chegar a 20 MB, 200 KB do log são apagados, começando
  pelas entradas antigas; as mais novas são preservadas.
[src:help-debug-setup] Set Up Debug Logging (sf.code_add_users_debug_log.htm): ver, guardar e apagar logs exige View All Data. Trace flags e debug
  levels se configuram no Developer Console (Debug, Change Log Levels) ou no Setup. Apagar um debug level apaga as trace flags que o usam.
[src:help-devconsole-logs] Logs Tab (sf.code_dev_console_tab_browser_logs.htm): os logs de usuário se configuram na página Debug Logs: Setup, Quick
  Find "Debug Logs". O nível de log define quanta informação da requisição é guardada; reduzir o nível reduz o tamanho do log.
[src:help-kb-traceflags-prod] Best practices for using debug logs with trace flags in Production (artigo 000395769): o limite padrão de
  armazenamento de logs de depuração é 1.000 MB; o artigo pede para não ligar trace flags em usuários de API ou em caminhos de código de alto volume.
[src:help-setup-audit-trail] Monitor Setup Changes with Setup Audit Trail (sf.admin_monitorsetup.htm): exige View Setup and Configuration. Caminho:
  Setup, Quick Find "View Setup Audit Trail". A tela mostra as 20 mudanças de Setup mais recentes, com data, autor e descrição; Download baixa o
  histórico completo dos últimos 180 dias; depois de 180 dias, os registros são apagados.
[src:help-security-audit] Monitor and Audit Security in Salesforce (xcloud.security_audit.htm): o Setup Audit Trail acompanha as mudanças recentes de
  Setup feitas pelos administradores, o que ajuda quando há vários; Field History Tracking registra quem mudou o quê e quando em campos escolhidos.
[src:help-kb-audit-changesets] Unable to track gained or lost User permission in Profile (artigo 000386467): mudanças de permissões de usuário feitas
  por change set não são registradas no Setup Audit Trail.
[src:help-event-monitoring] Event Monitoring (xcloud.real_time_event_monitoring_overview.htm): dá acesso a dados detalhados de desempenho, segurança
  e uso dos apps. Os dados se consultam por API; o Event Log File Browser, no Setup, dá acesso aos arquivos de log; há também os Real-Time Events,
  publicados pela Salesforce, que se podem assinar.
[src:help-em-enable] Enable Access to Event Monitoring (xcloud.real_time_event_monitoring_enable.htm): exige assinatura do Salesforce Shield ou do
  add-on Event Monitoring; ver eventos exige a permissão View Real-Time Event Monitoring Data.
[src:help-kb-em-faq] Salesforce Event Monitoring Frequently Asked Questions (artigo 000396295): retenção dos arquivos de log: Developer Edition, 1
  dia; Enterprise, Unlimited e Performance sem o add-on, tipos de evento limitados e 1 dia; com o add-on, 30 dias por padrão, extensíveis a 1 ano.
  O Real-Time Event Monitoring se configura no Event Manager, no Setup.
[src:help-kb-rtem-faq] FAQs for Salesforce Real-time Event Monitoring (artigo 000396594): Event Monitoring guarda logs de ocorrência, erro e
  desempenho no objeto EventLogFile; Real-Time Event Monitoring guarda eventos de acesso e de segurança em tempo real, fora do EventLogFile.
[src:help-rn-elf-browser] Access and Download Event Log File Data with the Event Log File Browser (release note, release 250): caminho: Setup, Quick
  Find "Event Log File Browser"; escolhe-se o período e baixa-se o arquivo como CSV.
