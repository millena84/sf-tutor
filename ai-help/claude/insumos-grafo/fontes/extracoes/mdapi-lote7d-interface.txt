[src:mdapi-customapplication] CustomApplication: sufixo .app, pasta applications; apps customizados desde a API 10.0 e apps padrão desde a 30.0;
  estende Metadata (fullName herdado); aceita o curinga * (até a API 29.0, só devolvia apps customizados). As tabelas não têm coluna Required: a
  obrigatoriedade vem das descrições. Apps padrão usam o prefixo standard__; apps de pacote, namespace__Nome. navType e uiType não são atualizáveis.
  Recuperar o app o inclui nos componentes Profile e PermissionSet do mesmo pacote. Uma substituição flexipage que é o padrão do app não pode ser
  excluída pela Metadata API. Renomeações na API 42.0: tab para tabs, WorkspaceMappings para AppWorkspaceConfig, customShortcut para customShortcuts,
  defaultShortcut para defaultShortcuts, customApplicationComponent para components. O corte entre as duas partes caiu no início da tabela de
  TabLimitConfig; os dois campos vieram na segunda parte. A descrição de workspaceConfig veio truncada na leitura.
  Exemplos XML: app do Lightning Experience (actionOverrides, brand, formFactors, label, navType, tabs, uiType e outros), app padrão e app de console.

[src:mdapi-layout] Layout (meta_layouts.htm): sufixo .layout, pasta layouts; API 13.0 e posteriores; estende Metadata (fullName herdado); aceita o
  curinga *. Recuperar o layout o inclui nos componentes Profile e PermissionSet do mesmo pacote. Um item de layout traz um só destes: component,
  customLink, field, scontrol, page, analyticsCloudComponent ou reportChartComponent. O corte entre as duas partes caiu na linha scontrol de
  LayoutItem. Enumerações não transcritas valor a valor: FeedItemType (29 valores), PlatformActionListContext (19 valores) e os valores de quick
  action de SummaryLayoutStyle. O exemplo XML usa miniLayoutFields e miniRelatedLists, que não constam das tabelas. A descrição de
  FeedLayoutFilter cita standardFilter, que não está na tabela.

[src:mdapi-compactlayout] CompactLayout: definido dentro de um CustomObject, objeto padrão ou external object (a página não dá sufixo nem pasta);
  API 29.0 e posteriores (external objects, 42.0); estende Metadata (fullName herdado); aceita o curinga *. Mostra os campos-chave de um registro no
  app móvel, no Lightning Experience e nas integrações com Outlook e Gmail. Aceita todos os tipos de campo, exceto text area, long text area, rich
  text area e multi-select picklist. No exemplo, compactLayouts fica dentro de CustomObject, com fullName, fields (repetido) e label.

[src:mdapi-lightningexperiencetheme] LightningExperienceTheme: sufixo .lightningExperienceTheme, pasta lightningExperienceThemes; API 42.0 e
  posteriores; a página não diz o que o tipo estende; aceita o curinga *. Para ativar um tema pela Metadata API, define-se activeThemeField em
  LightningExperienceSettings. Acesso especial: disponível quando a permissão S1DesktopAllowed está ligada. description: até 1000 caracteres;
  masterLabel: até 70; designSystemVersion: SLDS_v1 (padrão) ou SLDS_v2, desde 64.0; isDarkModeEnabled: padrão false, desde 65.0.

[src:mdapi-brandingset] BrandingSet: sufixo brandingSet, pasta brandingSets; API 40.0 e posteriores; estende Metadata (fullName herdado); aceita o
  curinga *. Disponível com Digital Experiences, Surveys ou Lightning Experience ligados; todos os usuários, inclusive guest, acessam. A página lista
  34 nomes de propriedade para temas do Lightning Experience (por exemplo BRAND_COLOR, BRAND_IMAGE, HEADER_BACKGROUND_COLOR, ACCENT_COLOR_1), todos em
  maiúsculas; parte só vale em SLDS 1 e parte só em SLDS 2. Imagens precisam ser asset files já existentes.
